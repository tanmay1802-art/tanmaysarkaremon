Python Socket Client and Server Example

A tiny TCP echo server and client to learn how network programs talk.

By Tanmay Sarkar Emon · Published 12 Oct 2026 · Updated 13 Oct 2026 · 4 min read

This guide is for learning. Run these commands only on your own lab or servers.

Sockets are how programs send data over a network. This example runs on one computer using the loopback address, so it stays inside your own machine.

server.py

import socket
s = socket.socket()
s.bind(("127.0.0.1", 5000))
s.listen(1)
conn, addr = s.accept()
data = conn.recv(1024)
conn.sendall(data.upper())
conn.close()

client.py

import socket
c = socket.socket()
c.connect(("127.0.0.1", 5000))
c.sendall(b"hello lab")
print(c.recv(1024))
c.close()

Start the server in one terminal, then run the client in another. You should see HELLO LAB come back.

Keep servers bound to 127.0.0.1 while you learn, so nothing outside your computer can connect.

What happens in each call

A socket is one end of a network connection. In the server, socket() creates it, bind() attaches it to an address and port, listen() marks it as ready to accept and accept() waits until a client arrives, returning a new connection object and the client address. In the client, connect() starts the conversation. After that both sides use sendall() and recv() on their connection until one calls close().

TCP is a stream

A common beginner surprise is that recv(1024) does not mean one message. TCP delivers a stream of bytes, so one send can arrive in two pieces, or two sends can arrive together. The small example works because the message is short, but real programs need a rule for where a message ends, such as a newline, a fixed length or a length number at the start.

Bytes and text

Sockets carry bytes, not strings. That is why the client sends b"hello lab" and why the response is printed as bytes. Use .encode() when sending text and .decode() when reading it, and choose one encoding such as UTF-8 for both sides.

A safer version of the server

The first version handles one client and then exits. This version uses a context manager so the socket closes even after an error, allows the address to be reused quickly and keeps serving in a loop.

import socket

with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
    s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    s.bind(("127.0.0.1", 5000))
    s.listen()
    while True:
        conn, addr = s.accept()
        with conn:
            data = conn.recv(1024)
            if not data:
                continue
            conn.sendall(data.upper())

Stop it with Ctrl+C. It still serves one client at a time, which is fine for learning. Later you can look at threads or the selectors module for several clients.

Fixing the usual errors

Address already in use appears when the old server is still running or the port is in its short waiting state. Find the process with ss -tlnp | grep 5000 or use SO_REUSEADDR as above. Connection refused means that nothing is listening on that address and port, so start the server first and check that both programs use the same number. If the client waits forever, the server may be waiting for data that was never sent.

Check it from outside Python

You can test the server without writing a client. Netcat sends a line and prints the answer, which proves whether the problem is in the server or the client.

echo "hello lab" | nc 127.0.0.1 5000

You can also watch the exchange in Wireshark by capturing the loopback interface with the filter tcp.port == 5000, which shows the handshake, the data and the close.

Keep it safe

While you learn, keep the server on 127.0.0.1 so only your own computer can reach it. If you later bind to 0.0.0.0 for a lab network, add a firewall rule, never trust the data that arrives, and limit the size you read.

Practice in your own lab

Extend the example in three small steps. First, make the server return the text in lower case instead of upper case. Second, make the client read a line from the keyboard and send it. Third, make the server print the address of each client it serves. After each step run the pair again and capture the traffic with Wireshark, so you can match your code to the packets.

Quick recap

A socket is an endpoint, TCP is a stream of bytes, and every program needs its own rule for the end of a message. Close sockets with a context manager and bind to loopback while testing.
