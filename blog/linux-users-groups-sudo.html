Linux Users, Groups and sudo for Beginners

Create a normal user, add it to a group and give limited admin rights.

By Tanmay Sarkar Emon · Published 12 Oct 2026 · Updated 13 Oct 2026 · 4 min read

This guide is for learning. Run these commands only on your own lab or servers.

Work as a normal user and use sudo only when you need it. This limits the damage from a mistake.

Create and inspect

sudo adduser labuser
id labuser

Groups

sudo groupadd students
sudo usermod -aG students labuser

Give sudo

sudo usermod -aG sudo labuser

Lock an account

sudo passwd -l labuser

Use a strong, unique password. ChangeMe123 style examples are only placeholders.

Where accounts are stored

Linux keeps users in /etc/passwd, password hashes in /etc/shadow and groups in /etc/group. The passwd file is readable by everyone because programs need to map user numbers to names, while shadow is readable only by root. Looking at your own line with getent passwd labuser shows the user ID, the primary group, the home folder and the login shell.

adduser or useradd

On Debian and Ubuntu, adduser is the friendly script. It creates the home folder and asks for a password. useradd is the low level command and creates very little unless you add options. Beginners usually want adduser. On Red Hat based systems, useradd is the normal command and it sets up a home folder by default.

The usermod -aG trap

The most common mistake in this topic is writing usermod -G students labuser without the -a. That replaces all the supplementary groups of the user, which can remove the sudo group and lock the user out of admin tasks. Always use -aG to append. Group changes also apply only to new login sessions, so log out and in, or check with id in a fresh shell.

id labuser
groups labuser

Use sudo with limits

Giving a user full sudo is easy but broad. For a service account or a helper, allow only the commands they need. Always edit with visudo because it checks the syntax before saving, and a broken sudoers file can stop everyone from using sudo.

sudo visudo -f /etc/sudoers.d/labuser
labuser ALL=(root) /usr/bin/systemctl restart apache2

After saving, sudo -l -U labuser lists what the user is allowed to run.

Lock, expire and remove

There are different levels of closing an account. passwd -l locks the password but SSH keys can still work. usermod --expiredate 1 disables the account fully for most login methods. deluser --remove-home removes the user and the home folder. Choose based on whether you want to keep the files for later checking.

sudo usermod --expiredate 1 labuser
sudo chage -l labuser

Check who has been using the system

The commands last and lastlog show recent logins, and who shows the people logged in now. In the authentication log, sudo lines record which user ran which command, which is useful when you audit a shared lab server. If you see an account you do not recognise, lock it and check when it was created before deleting anything.

Good habits

Give each person their own account and never share the admin password. Keep the sudo group small. Check for accounts with empty passwords with sudo awk -F: '($2=="") {print $1}' /etc/shadow, which should return nothing. Review the list of users every time you finish a lab, especially if you created test accounts for practice.

Practice in your own lab

Create two test users, put one in a new group and give the other a single allowed sudo command. Log in as each, run id and sudo -l, and try one command that should work and one that should fail. Then lock one account and confirm that login is refused. Finish by deleting both users, so you also practise cleaning up what you create.

Quick recap

Use a normal account for daily work, append groups with -aG, give sudo only for the commands that are needed, and choose the right way to close an account. Always confirm a change with id, groups or sudo -l instead of assuming it worked. Remember that group changes need a new login, and that a mistake in the sudoers file can lock out every administrator, which is why visudo exists. Review users regularly, remove test accounts and keep your notes up to date.
